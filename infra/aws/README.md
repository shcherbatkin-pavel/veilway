# Инфраструктура AWS Direct

Этот корневой модуль Terraform создаёт новую VPC с IPv4 и IPv6, публичную подсеть,
интернет-шлюз, группу безопасности с ограниченным доступом, экземпляр EC2
с Ubuntu 24.04 и шифрованием диска, а также Elastic IPv4. Он не подключается к ВМ
и не развёртывает VPN-приложение. Группа безопасности открывает Direct VPN на
публичном UDP/1194 и межоблачный транзит OpenVPN на UDP/1196 только с заданного
оператором статического IPv4 Yandex `/32`. AWS не открывает порт входа клиентов
Yandex UDP/1195.

В MVP состояние намеренно хранится локально и содержит конфиденциальные
инфраструктурные данные. Запускайте с `umask 077`, храните состояние и
`terraform.tfvars` на зашифрованном диске, никогда не коммитьте и не публикуйте их.
Учётные данные AWS читаются только из стандартной цепочки учётных данных
провайдера AWS.

Созданный ULA сохраняется в состоянии этого модуля. Замена или потеря состояния
изменяет клиентскую подсеть IPv6 и требует новых профилей. Тот же постоянный
`/48` также выделяет отдельные сети `/64` для multi-hop-клиентов и транзита
Yandex–AWS.

При создании экземпляра автоматическое назначение публичного IPv4 явно отключено;
в подсети также отключён `map_public_ip_on_launch`. Elastic IP управляется
отдельным ресурсом. После его подключения провайдер AWS видит
`associate_public_ip_address` включённым; настройка жизненного цикла игнорирует
только это наблюдение после создания, чтобы избежать необоснованной замены экземпляра.

Точка доступа к метаданным EC2 включена в минимальной конфигурации для первого
запуска: Ubuntu cloud-init получает выбранный публичный SSH-ключ EC2 из метаданных
экземпляра. Токены IMDSv2 обязательны, предел переходов ответа равен единице,
точка доступа IPv6 и теги метаданных отключены. У экземпляра нет профиля IAM,
поэтому IMDS не может выдавать учётные данные роли AWS. Межсетевой экран хоста
независимо запрещает VPN-клиентам доступ к адресам метаданных IPv4 и IPv6.
