# Миграция существующих VPN-профилей

Сохраняются действующий CA Veilway и исходные `.ovpn`. Импорт не выпускает
сертификаты, не меняет ключи, директиву remote или сроки и не заменяет серверные
и транзитные идентификаторы на VPN-узлах. OpenVPN Access Server не затрагивается.
Выполнение рабочих команд требует точного согласования по `AGENTS.md` и
[операторской инструкции](profile-rollout.md).

## Контракт

CA импортируется отдельно по прежнему списку разрешённых файлов. Для клиентских
материалов предусмотрен отдельный `import-profiles`. После разрешения на
чтение/копирование реальных профилей подготовить согласованную резервную копию
CA, профилей и базы и остановить локальные источники записи. Исходные файлы
находятся в `client-profiles/*.ovpn`: старый CLI удалял отдельные клиентские
ключи после создания, но сохранил их внутри `.ovpn`. Отдельный клиентский
сертификат не позволяет восстановить ключ.

В защищённом каталоге вне Git и контекста сборки подготовить только
`manifest.json` и явно перечисленные `.ovpn`. Каталоги `0700`, файлы `0600`;
на ВМ числовой владелец 10002. Символические и жёсткие ссылки запрещены.
Имена файлов — ASCII без путей, до 133 символов включая `.ovpn`.
В комплекте 1–1000 файлов; для большего количества использовать несколько
комплектов. Пример с вымышленными именами:

```json
{
  "version": 1,
  "profiles": [
    {"file": "laptop-yc-direct.ovpn", "mode": "yc-direct", "device_name": "Laptop"},
    {"file": "phone-aws-direct.ovpn", "mode": "aws-direct", "device_name": "Phone"},
    {"file": "tablet-yc-aws-multihop.ovpn", "mode": "yc-aws-multihop", "device_name": "Tablet"}
  ]
}
```

Владельцев ADMIN назначает зарегистрированным USER в панели после синхронизации.
Имя файла, CN и название устройства не определяют учётную запись Google.
Материалы не передаются через браузер/API/stdin бэкенда. В PostgreSQL попадают
только UUID, имя, режим, даты, состояние, серийный номер и отпечатки.
Пароль и учётные данные хранятся отдельно от резервной копии.

Импорт проверяет:

- Точный набор безопасных директив Veilway и четыре встроенных блока `ca`,
  `cert`, `key`, `tls-crypt-v2`. Порядок/комментарии допустимы; дубли, плагины,
  скрипты, внешние файлы и дополнительные директивы remote отклоняются.
  Конфигурация не запускается.
- Совпадение CA, подписанного сертификата с `newcerts`/реестром, серийного
  номера/срока, clientAuth, CA:false и закрытого ключа с сертификатом.
- Аутентичность обёрнутого `tls-crypt-v2` относительно серверного ключа нужного
  режима. Формат сверён с [OpenVPN 2.6](https://github.com/OpenVPN/openvpn/blob/v2.6.12/src/openvpn/tls_crypt.c).
- Точку доступа согласно настройкам режима. Исходный порт AWS Direct 443
  разрешён наряду с 1194, без переписывания; доступность исходного порта
  проверяется на реальной инфраструктуре.

Сохраняются все исходные байты `.ovpn`. Истёкшие/отозванные профили импортируются
как история и не скачиваются; CRL не меняется. Нестандартный или неполный файл
отклоняется без перевыпуска и без изменения старого клиентского доступа.
Для такого формата требуется отдельное расширение контракта, а не ручная
подмена материалов. UUID определяется сертификатом и CA. Повтор под новым
именем или режимом конфликтует; один серийный номер не создаёт несколько профилей.

## Операторский порядок

1. Выполнить резервное копирование при остановленной записи, передачу управления
   и импорт **того же** CA по операторской инструкции. Сохранить серверные/
   транзитные сертификаты и ключи обёртки на узлах. Завершить вход Google ADMIN
   и получить его UUID из `/api/v1/auth/session`; не выводить
   cookie/CSRF/учётные данные в журналы.
2. Отдельно согласовать остановку `api web pki`, закрывая все серверные
   источники записи. Локальная запись уже заблокирована передачей управления.
   VPN продолжает работать.
3. Выполнить импорт из подготовленного закрытого каталога:

   ```bash
   docker compose --file /opt/veilway-control/app/compose.yaml stop api web pki
   docker compose --file /opt/veilway-control/app/compose.yaml run --rm --no-deps \
     --volume /private/approved-legacy-profiles:/import:ro \
     pki import-profiles --source /import
   docker compose --file /opt/veilway-control/app/compose.yaml up --detach pki
   ```

4. При остановленных API/web синхронизировать метаданные через Unix-сокет.
   Ниже заменить вымышленный UUID фактическим UUID закреплённого Google ADMIN:

   ```bash
   docker compose --file /opt/veilway-control/app/compose.yaml run --rm --no-deps \
     api veilway-control import-legacy-profiles \
     --admin-id 00000000-0000-4000-8000-000000000001
   ```

   Каталог постраничный, привязан к поколению PKI; смена поколения вызывает
   отказ. Вся пачка метаданных фиксируется одной транзакцией. Новые задания
   подписи не создаются; до синхронизации материалы не видны в панели.
5. Проверить коды завершения, затем отдельно согласованно запустить `api web`.
   ADMIN назначает владельцев через существующий экран. USER видит сроки
   и скачивает свои действующие профили. В истории есть событие импорта.
6. До открытия выдачи выполнить приёмку исходных клиентских файлов на реальной
   инфраструктуре для всех режимов и проверить условия CRL. Сверить
   сертификаты/ключи/сроки/скачанные байты в защищённой среде. Для теста отзыва
   использовать отдельный временный профиль, не существующий пользовательский
   доступ. Сделать согласованную резервную копию после переноса.

## Сбой и восстановление

PKI фиксирует комплект атомарно сменой `CURRENT`. Ошибка до фиксации не публикует
профили и не меняет реестр/CRL/счётчики. Сбой после фиксации восстанавливается
повтором того же комплекта. Следующая транзакция удаляет только служебные
неопубликованные поколения.

После успешного импорта PKI и неудачной синхронизации повторить синхронизацию
при закрытой для записи панели. Она не сбрасывает имена, владельцев и состояние
уже запущенного отзыва. Не откатывать CA, не создавать второй профиль
и не перевыпускать сертификат для исправления ошибки базы.

Резервная копия включает полное поколение PKI с исходными клиентскими
материалами/записями/подтверждениями и PostgreSQL с владельцами, происхождением,
аудитом и заданиями. Восстанавливать согласованную пару по операторской
инструкции без уменьшения счётчиков, потери отзывов и сброса защиты
CRL-агента от отката. Миграция `0006_legacy_profiles` блокирует откат
при наличии импортированных записей или событий.
