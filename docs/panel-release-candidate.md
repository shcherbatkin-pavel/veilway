и проверить его локально. Это не развёртывание и не разрешение на изменения ВМ.

phases (#5)`). Изменения Google/профилей/PKI и миграции M1–M3 находятся в рабочем
дереве: есть изменения отслеживаемых и новые неотслеживаемые файлы. Индекс пуст.

добавлены правила PR/squash merge; они не меняют работу приложения.

Полный состав публичных исходников кандидата и SHA-256 каждого файла —
[манифест](panel-release-candidate.json). Он исключает закрытый инвентарь,
`.env`, CA, профили, результаты сборки, кэши и сам отчёт/манифест. Контрольные
суммы описывают локальные исходники, а не опубликованные образы. Перед
развёртыванием нужны прошедшая ревью ревизия, сверка файлов с кандидатом
и фиксация фактических ID/дайджестов образов в защищённом операторском журнале.
Теги `:0.1.0` сами по себе версию не доказывают; развёртывание сейчас
собирает образы на ВМ с `--pull`.

Манифест содержит 226 публичных файлов, в том числе 79 рабочих входов панели.
SHA-256 рабочего состава: `b41631f4c9a36f4b249ef48a5b1c9cae7020883da39dad6459a0e9501abb7529`.
Группы `panel_deployment` и `node_and_support_deployment` раздельны: наличие
файлов второго этапа не означает развёртывание узлов при применении web.
Созданные кэши/egg-info игнорируются Git и не входят в манифест исходников;
для рабочей системы используйте чистую копию ревизии, прошедшей ревью.

Этот отчёт и контрольные суммы фиксируют исторический кандидат M4.1.
Позднейший перевод документации не обновляет снимок исходников в манифесте;
его суммы относятся к файлам кандидата на момент фиксации, а не к текущему дереву.

## Состав и поведение обновления

| Часть | Что входит | Изменение поведения |
| --- | --- | --- |
| Бэкенд/API | Google OIDC, роли/владение, профили/задания, издатель CRL, синхронизация старых профилей | Вход через Google; USER скачивает только своё; ADMIN назначает/отзывает |
| PostgreSQL | Alembic 0002–0006 поверх 0001 | История сохраняется; старые сессии отключаются; появляется происхождение импорта |
| Фронтенд/Caddy | Кабинеты ADMIN/USER, история/узлы/CRL, no-store и обработка callback | Парольный вход заменён Google; импорт виден в истории |
| PKI | Отдельный изолированный контейнер, Unix-сокет, import-ca/import-profiles | Тот же CA и исходные `.ovpn`; без перевыпуска, новых владельцев задаёт ADMIN |
| Развёртывание панели | Роль control-web, разрешённые входы сборки, секреты и постоянное хранилище | Останавливает API/web и имеющийся PKI перед миграцией; сохраняет БД |
| Инструменты оператора | Защищённая обёртка и передача локальной записи серверу | `.env` читается операторской обёрткой; после передачи локальная выдача блокируется |
| Этап CRL VPN | Агент, управляемые монтирования и защита от старого локального CRL | Отдельная операция на узлах после явного согласования |

Применение панели устанавливает зависимости и настраивает выделенный диск данных,
монтирование/tmpfiles, создаёт сети Docker, собирает образы, применяет миграции,
синхронизирует ВМ/хеши токенов и запускает API/web/PKI. Оно не импортирует
CA/профили автоматически и не переключает монтирования CRL VPN-узлов.
PKI без CA остаётся недоступной для выдачи. Последовательность импорта —
[инструкция](legacy-profile-migration.md). Нельзя выдавать доступ до проверки
публикации/подтверждений и старых подключений.

CA, серверные/транзитные идентификаторы, ключи обёртки, точки доступа и исходные
клиентские файлы сохраняются. Нужные изменения конфигурации/контейнеров CRL
согласуются отдельно; существующий OpenVPN Access Server остаётся неизменным.
Ротация/создание/удаление CA через ADMIN-панель — будущие C1–C4, не часть кандидата.

Не проверялись реальные учётные данные Google, SSH, данные ВМ/диска,
материалы CA/профилей и реальный VPN: первая итерация ограничена публичными
исходниками и искусственными временными тестовыми данными.

Перед изменениями ВМ отдельно требуются прошедший ревью выпуск через PR,
защищённые пути инвентаря/входов и согласованная резервная копия.
Для M4.3–M4.5 нужны точные разрешения на экспорт/передачу управления,
остановку панели, импорт и изменения CRL выделенных узлов по
[операторской инструкции](profile-rollout.md) и `AGENTS.md`.

Следующая маленькая итерация **M4.2** — определить защищённое место копии,
подтвердить инвентарь и согласовать операции/окно обслуживания.
Коммит/PR/отправка/применение/экспорт/передача управления в M4.1 не выполнялись.
