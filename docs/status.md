инструменты автоматически. SQLite не заменяет PostgreSQL acceptance, а тот
не заменяет операторский migration/sync/backup smoke.

## Последнее документированное развёртывание

**2026-10-14: панель обновлена до согласованного состава main `722718d`**
после PR #26/#27. Основание: разрешённые оператором проверка единственной
панели, согласованная копия и обновление только образов API/web/PKI.
Контейнер PostgreSQL сохранён; схема уже была `0009_mobile_client`,
миграции не выполнялись. Секреты, базовый Compose и рабочие пути сохранены;
VPN-узлы, агенты, облачные ресурсы и Access Server не изменялись.

Перед обновлением сохранена парная копия БД и полного PKI в прежнем закрытом
месте. Проверены tar-сравнение, контрольные суммы передачи и восстановление
БД в одноразовой PostgreSQL 17.4 без внешней сети/портов. При проверке временной
БД готовность подтверждалась реальным SQL-запросом по TCP. Первая копия
сохранена отдельно; после временного возобновления старых контейнеров взята
и проверена новая согласованная копия перед окончательным переключением.

Проверены точные ID работающих образов, неизменность контейнера БД,
метаданные PKI-сокета под штатным UID и отсутствие ошибки CRL-worker.
Публичные HTTPS health/ready возвращают ожидаемые ответы; анонимные
browser/mobile запросы профилей отклоняются. Это техническая приёмка
развёртывания, а не ручная проверка Google-входа или пользовательского VPN.
Активный image override, прежние ID для отката и копия записаны в
игнорируемом `operator-config/panel-release.json` (0600). Последующие
операции Compose должны включать этот override по [руководству](profile-rollout.md).

Исторический журнал M4 от **2026-10-07** в
[плане переноса](pki-evolution-plan.md#журнал) сохранён как датированная история.
Закрытые операторские записи дополнительно фиксируют завершение согласованной
миграционной приёмки 2026-10-09. Этот выпуск не повторял handover/import CA,
импорт клиентских материалов или переключение CRL-монтирований.

Исторические ADR 0002/0003 и прежняя дорожная карта описывали фильтрацию
прямого пути AWS, приёмку Yandex и multi-hop Ubuntu/iPhone. Они не являются
свежей проверкой сетей на 14 октября; дата последующей клиентской приёмки
в прежней дорожной карте не указана.

**Android 0.1.3-pilot опубликован 2026-10-14** вместе с соответствующим
архивом исходников и SHA256SUMS. Подпись существующего APK проверена до
публикации. Фактические байты всех восьми APK/архивов по HTTPS совпали с
закреплёнными SHA-256; MIME, attachment/cache, range и 404 проверены.
Кнопка инструкции ведёт на 0.1.3; прежние версии 0.1.0–0.1.2 сохранены.
Ручная Android-приёмка остаётся отложенной.

[Кандидат M4.1](panel-release-candidate.md) и
[пример API/web PR #9](api-web-rollout.md) сохраняют свои даты, ревизии и хеши;
их нельзя выдавать за комплект текущего выпуска.

## Оставшиеся отдельные задачи

На 2026-10-14: ручная Android-приёмка и функциональная приёмка нового
выпуска через Google/профили/VPN. Публикация 0.1.3 и техническое обновление
панели завершены; реальные перезапуски VPN-узлов этим выпуском не выполнялись.

C1–C4 управления CA, CI, изменение зависимостей, оптимизация SQL/PKI после
измерений и отдельное управление ресурсами Android VPN-сеанса остаются
самостоятельными будущими задачами. Они не являются незавершённой реализацией №12.
Запреты на рабочие материалы, автоматические подключения, телеметрию и
изменения Access Server сохраняются по [AGENTS.md](../AGENTS.md).
