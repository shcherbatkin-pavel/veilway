# ADR 0006: Модели по областям и границы рефакторинга

- Статус: принято для реализации №12; слияние отслеживается в [статусе](../status.md).
- Дата: 2026-10-14.
- Основание: завершённые P1/P2 в PR #19–25 и монолит ORM на `409a2ff`.

## Решение

`veilway_control.models` — пакет auth/profiles/nodes/restart/crl/analytics.
`shared.py` содержит UTC-функции; `__init__.py` сохраняет прежние импорты
классов, `Base`, функций и VM-констант. Домены импортируются явно в исходном
порядке. Единственный registry и metadata принадлежат `database.Base`.
Межобластные аннотации используют `TYPE_CHECKING`; SQLAlchemy разрешает
отложенные relationships через тот же registry.

`mobile_models.py` остаётся отдельным: пакет не импортирует его и не меняет
момент регистрации мобильных таблиц. Alembic по-прежнему явно импортирует
оба модуля. Таблицы, DDL, ограничения, индексы, defaults, cascade, foreign keys
и миграции сохраняются. Перемещение классов не уменьшает связанность данных
и не требует универсального repository или нового DeclarativeBase.

Публичный `tests/fixtures/client-contract.properties` в backend задаёт общую
проверочную лексику режимов/статусов/ролей/заданий и device-login ошибок.
Python сравнивает её с Pydantic, SQL constraints и HTTP; TypeScript compiler API —
с union-типами потребителей; Kotlin JVM — с доступностью профиля и polling.
Kotlin проверяет только используемую часть, сохраняя строковые поля.
Fixture входит в тестовые resources и архив Android-исходников; в APK runtime
он не добавляется. Генерации клиентов и новых зависимостей нет.

## Сохранённые границы P1/P2

- HTTP, схемы и расчёты аналитики разделены. Приём событий сохраняет одну
  транзакцию и блокировку агента; вспомогательные этапы не вызывают commit.
- Mobile HTTP валидирует входы и строит ответы; сервис владеет сценарием,
  независимой фиксацией rate-limit и одноразовым обменом под блокировкой.
  Общий download нейтрален к router; прежние dependency overrides сохраняются.
  Mobile-download ограничен владельцем даже для ADMIN.
- `Store` владеет блокировкой, поколениями, receipt, восстановлением и commit.
  Файловые примитивы сохраняют O_NOFOLLOW/права/fsync; allowlist команд,
  sealed memfd, timeout и фиксированные ошибки остаются в адаптере.
  Совместимые импорты `core`/`Store.run` сохранены. Формат и copy-on-write
  не оптимизируются без репрезентативных измерений и crash-проверок.
- Frontend сохраняет фильтры/пагинацию/выбор и snapshot key в родителе.
  График/чистая геометрия, представления и форматирование отдельны;
  устойчивые ключи сохраняют раскрытые детали. `useProfileActions` владеет
  блокировкой, CSRF, потерей авторизации и исходными key/payload повторов.
  Restart в Nodes остаётся своим сценарием; порядок CSS-правил сохраняется.
- Android `MobileSession` защищает cancel/logout и поздние ответы;
  `StoredLogin` сохраняет формат. Подключённый туннель и удерживаемый
  блокирующий TUN — разные состояния. Native handle и порядок закрытия FD
  требуют самостоятельных устройственных проверок.
- Verification статически импортирует шесть последовательных task-групп;
  команды, условия, циклы, changed_when/no_log остаются прежними.
  Heartbeat, CRL и analytics агенты не объединяются в транспортный framework.
- Независимые Terraform roots и политики AWS/Yandex сохраняются.
  CLI управляют защищёнными/игнорируемыми входами и атомарной записью 0600;
  чистые диагностические парсеры и политики не читают рабочие state/секреты.
- Инспектор релиза автономен и содержит единственный INPUTS. Упаковщик
  импортирует фиксированный обычный файл локально; предусловия хеширования,
  manifest и checker_sha256 не ослабляются.
- Restart и PKI job имеют разные правила повтора: неопределённый reboot
  требует ручного рассмотрения, PKI сохраняет исходный durable key.
  Проверки CRL на backend и агенте остаются независимыми границами доверия.

## Приёмка и сопровождение

Baseline фиксирует регистрацию и fingerprints DDL SQLite/PostgreSQL,
defaults и relationships до перемещения. Новые проверки запускают fresh-process
imports в разных порядках и configure_mappers; существующая PostgreSQL-приёмка
применяет миграции и требует пустой Alembic metadata diff.
OpenAPI сравнивается до/после, [полная матрица](../test-matrix.md) сохраняет
SQLite, PostgreSQL acceptance, операторский smoke, PKI, браузер, native accounting
и Android JVM/lint. Недоступные обязательные проверки не считаются успешными.

README — навигация; [status.md](../status.md) — датированные состояния;
roadmap — последовательность развития; руководства — инструкции;
планы/кандидаты/журналы — история. Старые ADR, миграции и legacy-процедуры
не удаляются только из-за возраста. Временный обзор удаляется после переноса
действующих ограничений и непроверенных операторских/ручных шагов.

Ни один рефакторинг не разрешает развёртывание, изменение VPN/маршрутов/firewall,
телеметрию или операции с рабочими материалами. Access Server не затрагивается.
PR в main сливаются squash после проверок и закрытия обсуждений по AGENTS.md.
