# Android-клиент Veilway: сборка и пилот

Нативный клиент `ru.veilway.android` работает на Android 10+ (API 29), ARM64
и x86_64. Kotlin/Compose отвечает за интерфейс, OpenVPN 3 Core через JNI —
за протокол, Android VpnService — за выбор приложений. Профили и токен
шифруются AES-GCM ключом Android Keystore в `noBackupFilesDir`. Резервное
копирование и перенос данных отключены; секреты не передаются через Intent.
Телеметрии и журналирования трафика/профилей нет.

## Сборка на Linux

Нужны JDK 17+ (проверено с 21), Python 3.12+, curl, Perl, make, Android SDK:
platform 35, build-tools 35.0.0, NDK 27.2.12479018, CMake 3.22.1. Подготовка
SDK — явный шаг разработчика; скрипты не устанавливают системные пакеты.
Укажите SDK через `ANDROID_HOME` или игнорируемый `android/local.properties`.

```bash
python3 scripts/prepare-android-native.py --download --sdk-root /path/to/sdk
python3 scripts/android-pilot-key.py
cd android
./gradlew --download-gradle assembleRelease testDebugUnitTest lintDebug
cd ..
python3 scripts/package-android-pilot.py --sdk-root /path/to/sdk
```

`--download` явно разрешает загрузки архивов из закреплённого манифеста,
проверяемых SHA-256. `--download-gradle` явно разрешает первую загрузку Gradle;
сам Gradle разрешает зависимости из Google Maven/Maven Central по lockfile и
метаданным проверки. При повторных сборках эти флаги необязательны при наличии
кеша. Не используйте `--write-locks` или `--write-verification-metadata` для
обычной сборки: обновление зависимостей требует отдельного ревью.

Ключ подписи создаётся один раз в игнорируемом `private/android`, с закрытыми
правами и без печати пароля. Сохраните закрытую резервную копию: последующие
APK должны подписываться тем же ключом. Скрипт упаковки проверяет подпись,
создаёт APK, SHA256SUMS, инструкцию и соответствующий архив исходников в
`release-artifacts/android`. Передавайте архив исходников вместе с APK,
сохраняя требования MPL-2.0 и уведомления остальных библиотек.

## Вход и контракт API

Все мобильные пути начинаются с `/api/v1/mobile`; ответы запрещают кеширование.

- `POST /auth/device`: возвращает `device_code`, `user_code`, адрес подтверждения,
  срок 600 секунд и интервал опроса 5 секунд. Человеческий код передаётся в
  URL-фрагменте, не в HTTP-запросе; браузер сохраняет только его в sessionStorage
  на время Google-входа. Подтверждение требует явного нажатия пользователем.
- `POST /auth/approve`: браузерная cookie + CSRF, JSON `user_code`. Код нельзя
  подтвердить повторно. Получать мобильный токен этим маршрутом невозможно.
- `POST /auth/token`: JSON `device_code` и необязательный `grant_type` со значением
  `urn:ietf:params:oauth:grant-type:device_code`. Ошибки `authorization_pending`,
  `slow_down`, `expired_token`, `access_denied`. Обмен одноразовый, сериализован
  блокировкой PostgreSQL. Это JSON-контракт Veilway по модели RFC 8628.
- `POST /auth/logout`: Bearer-токен, отзыв текущей мобильной сессии.
- `GET /profiles?limit=100&offset=0` и `POST /profiles/{id}/download`: Bearer-токен,
  только профили владельца, в том числе для ADMIN. Действуют существующие правила
  активности/срока, аудит и изолированная PKI. Административные API не принимают
  мобильные токены. Сессия действует 30 дней, без refresh; БД хранит только хеш.

Лимиты постоянные и общие для API-процессов: создание 30/минуту, опрос
300/минуту; подтверждение 20/10 минут на аккаунт и 100/10 минут суммарно.
Не доверяем произвольным X-Forwarded-For и не сохраняем IP. После слишком
частого опроса интервал конкретного устройства увеличивается на 5 секунд,
до 60. При отказе API новое подключение запрещено, восстановление уже
установленного туннеля от API не зависит.
Мобильные тела запросов ограничены 4 КиБ до разбора JSON, включая chunked.

Выход сначала останавливает VPN и удаляет локальные секреты. Если сервер
недоступен, приложение сообщает, что серверный отзыв не подтверждён;
серверная сессия сохраняется до своего срока либо ручного отзыва оператором.

## Маршрутизация и граница блокировки

Режим один: только выбранные установленные приложения через VPN. Пустой
список запрещён. Удалённые приложения исключаются перед новым подключением;
если не осталось ни одного, подключение не начинается. Снимок списка
фиксируется на подключение. Клонированные приложения выбираются отдельно.

Служба создаёт блокирующий TUN до получения профиля, затем заменяет его
интерфейсом OpenVPN без предварительного снятия блокировки. Она удерживает
собственный дескриптор; ядро получает дубликат. При переподключении закрытие
дескриптора ядром не возвращает выбранным приложениям прямой маршрут.
Перехватываются IPv4/IPv6; неиспользуемые семейства не обходят VPN, DNS
берётся из сервера, `block-ipv6` профиля сохраняется. Локальные исключения
маршрутов не разрешают выбранным приложениям выход вне туннеля.

Блокировка действует до явного отключения и только при живой службе/TUN.
Системная остановка, force-stop, отзыв разрешения или другой VPN снимают её.
Always-on отключён. Неподдерживаемые/внешние конфигурации, скрипты, ослабленная
проверка сервера или TLS отклоняются; продукт поддерживает профили Veilway.

## Проверки и развёртывание

Запустите `./scripts/check.sh`, тесты backend/frontend и Android unit/lint.
PostgreSQL-тесты `test_mobile_postgres.py` проверяют конкурентный одноразовый
обмен и отсутствие потерянных обновлений лимита на отдельной тестовой БД.

Для настоящего JNI/TUN-теста соберите `assembleDebug assembleDebugAndroidTest`,
запустите отдельный Android-эмулятор и выполните:

```bash
python3 scripts/test-android-tunnel.py --sdk-root /path/to/sdk --serial emulator-5556
```

Тест использует временную синтетическую PKI, локальный Docker-образ
`veilway/openvpn:2.6-ubuntu24.04`, TUN и NET_ADMIN внутри нового контейнера,
порты только localhost 18080/UDP и 18081/TCP. Проверяет IPv4, IPv6, DNS,
разные UID, блокировку при отказе и восстановление. Debug-only приёмник
фикстуры отсутствует в release APK; разрешение cleartext есть только в debug.
Тест не подключается к рабочим узлам и не читает их материалы или журналы.

Перед пилотом оператор отдельно согласует обновление API/панели и применение
миграции `0009_mobile_client` по существующей процедуре выпуска. Google
callback не меняется; VPN-узлы, CA и рабочие профили перевыпускать не нужно.
Сделайте защищённую резервную копию БД; проверяйте готовность сервиса после
миграции и вход/скачивание под USER. При откате приложения API оставьте
совместимое расширение БД; удаление мобильных таблиц отзывает все сессии и
является отдельным согласованным действием. Подпись и APK не разрешают
развёртывание или изменения существующего OpenVPN Access Server.

Протокол приёмки на телефоне — [инструкция пользователя](android-pilot-user.md).
Эмулятор не подтверждает работу OZON, особенности энергосбережения телефона,
Wi-Fi/мобильного оператора или Google-вход на рабочем сайте.

## Публикация APK в инструкции панели

Веб-образ содержит только APK, соответствующие исходники и SHA256SUMS.
Закреплённые хеши находятся в `web/frontend/android-release.json`. Для локальной
сборки сначала подготовьте игнорируемый Git каталог (он должен отсутствовать):

```sh
node web/frontend/stage-android-release.mjs --stage release-artifacts/android/web-downloads web/frontend/android-release
docker build --tag veilway-control-web:android-download web/frontend
```

Для проверки раздачи запустите образ на localhost с тестовым HTTP-слушателем
и выполните `python3 scripts/test-android-downloads.py --base-url http://127.0.0.1:18089`.
Проверка сверяет скачанные файлы с закреплёнными хешами, MIME, заголовки кеша,
докачку и отсутствие SPA-страницы вместо 404.

Сборка останавливается при отсутствии файлов, неверных хешах или лишних файлах
в подготовленном каталоге. Скрипт подготовки API/web-релиза также включает
артефакты из `release-artifacts/android/web-downloads` (либо `--android-release`); изменения
Dockerfile/Caddyfile требуют отдельного ревью конфигурации и не обходят его
проверку совместимости. Выкладываются только публичные артефакты, без INSTALL.md,
ключей подписи или локальных настроек. Развёртывание выполняется отдельно.

При следующем выпуске используйте тот же ключ подписи, новое имя APK и архива,
обновите закреплённые хеши и ссылки инструкции. Версионные файлы не заменяйте:
они кешируются на год как неизменяемые. SHA256SUMS кешируется с обязательной
перепроверкой, поскольку его адрес сохраняется между выпусками.

## Обновление 0.1.1-pilot

Отмеченные приложения сразу перемещаются наверх списка; внутри обеих групп
сохраняется порядок по названию. Поиск применяется к обеим группам. Изменение
выбора по-прежнему вступает в силу для туннеля при следующем подключении.
VersionCode увеличен до 2 для установки поверх 0.1.0 с тем же ключом подписи.
Скрипт упаковки определяет версию из метаданных APK и сохраняет каждый выпуск
в `release-artifacts/android/<version>/`, не заменяя артефакты 0.1.0.

Каталог `web-downloads` содержит текущий и ранее опубликованные APK с
соответствующими архивами исходников; SHA256SUMS перечисляет все эти файлы.
Перед публикацией нового выпуска добавьте его хеши в манифест веб-панели и
сформируйте каталог только из перечисленных файлов. Старые версионные URL
сохраняются, кнопка инструкции ведёт на текущий выпуск.

## Обновление 0.1.2-pilot

Ожидание подтверждения входа сохраняет исходный код и его срок действия при
временной сетевой ошибке или HTTP 5xx. Повторные запросы идут с увеличенным
интервалом (до 60 секунд); отмена прекращает их. Ошибки TLS, неверного JSON,
истечения и отказа доступа показываются отдельно. Отменённая попытка не удаляет
данные следующей попытки. Если сервер выдал одноразовый токен, но ответ потерян,
повторная выдача не разрешается: понадобится новый вход.
